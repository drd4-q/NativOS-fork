# Архитектура дисплея и графического стека Qualcomm (Xiaomi M17 / Snapdragon 695)

Данный документ содержит полное описание аппаратной архитектуры экрана, видеостека ядра Linux/Qualcomm, особенностей работы DRI3/Turnip и концепции прямого вывода DRM/KMS для устройств на платформе Qualcomm Snapdragon (в частности, Xiaomi M17 / `moonstone`).

---

## 1. Паспорт дисплея и платформы

Данные получены при аппаратном сканировании ядра `Linux 5.4.302-Protium`:

* **Устройство**: Xiaomi POCO X5 5G / Redmi Note 12 5G (модель `22111317PG`, кодовое имя `moonstone`).
* **Платформа (SoC)**: Qualcomm Snapdragon 695 5G (`holi` / `SM6375`).
* **GPU**: Qualcomm Adreno 619.
* **Идентификатор панели экрана в DTB / cmdline**:
  ```text
  msm_drm.dsi_display0=qcom,mdss_dsi_m17_38_0c_0a_fhdp_dsc_vid:
  ```
* **Расшифровка обозначения панели**:
  * **M17**: Внутреннее заводское обозначение дисплейного модуля Xiaomi.
  * **FHDP**: Разрешение Full HD+ (**1080 × 2400** пикселей).
  * **DSC**: *VESA Display Stream Compression* — аппаратное сжатие видеопотока в реальном времени, необходимое для прокачки 1080p @ 120Hz по 4 линиям MIPI DSI без задержек.
  * **VID**: Режим *Video Mode DSI* (контроллер дисплея DPU непрерывно шлет кадры синхросигналами HSYNC/VSYNC, в отличие от *Command Mode* со встроенным в панель буфером GRAM).
* **Поддерживаемые режимы развертки (`/sys/class/drm/card0-DSI-1/modes`)**:
  * `1080x2400 @ 120 Hz` (основной высокоскоростной режим)
  * `1080x2400 @ 60 Hz` (энергосберегающий режим)
* **Управление подсветкой**:
  * Системный узел: `/sys/class/backlight/panel0-backlight`
  * Механизм: команды яркости передаются драйвером через DSI DCS-пакеты (`dsi_set_backlight_control`).

## 2. Архитектура видеостека Qualcomm Snapdragon в Android

В отличие от ПК (где драйверы `amdgpu` или `i915` управляют и 3D-вычислениями, и дисплеем через один общий узел `/dev/dri/card0`), в чипсетах **Qualcomm** в Android-ядре действует **двухкомпонентная разделенная архитектура**:

```
 ┌────────────────────────────────────────────────────────┐
 │                     ПРИЛОЖЕНИЯ                         │
 └───────────┬────────────────────────────────┬───────────┘
             │                                │
      [Vulkan / Turnip]               [SurfaceFlinger / HWC]
             │                                │
             ▼                                ▼
 ┌───────────────────────────┐  ┌───────────────────────────┐
 │     3D GPU (Adreno 619)   │  │ Display Engine (MDSS/DPU) │
 │  Ядерный драйвер: KGSL    │  │  Ядерный драйвер: MSM DRM │
 │    Узел: /dev/kgsl-3d0    │  │   Узел: /dev/dri/card0    │
 └───────────────────────────┘  └─────────────┬─────────────┘
                                              │
                                              ▼ (MIPI DSI + DSC)
                                ┌───────────────────────────┐
                                │   Панель Xiaomi M17       │
                                │   (1080x2400 @ 120Hz)     │
                                └───────────────────────────┘
```

1. **3D GPU (Adreno 619)**:
   * Не имеет стандартного DRM-интерфейса в ядре Android.
   * Управляется драйвером **KGSL** (*Kernel Graphics Support Layer*) через символьное устройство `/dev/kgsl-3d0`.
   * Драйвер с открытым исходным кодом **Mesa Turnip (Freedreno)** содержит специальный бэкенд для работы с KGSL напрямую из chroot/Linux без необходимости в DRM-рендерере.
2. **Display Controller (MDSS / SDE / DPU)**:
   * Контроллер физического вывода изображения Snapdragon Display Engine управляется драйвером `msm_drm`.
   * Зарегистрирован в ядре как `/dev/dri/card0` с коннектором `/sys/class/drm/card0-DSI-1`.
   * Отвечает исключительно за развертку, смешивание слоев (*Hardware Planes*), калибровку цветов, DSC-компрессию и передачу пикселей по шине DSI на панель M17.

## 3. Почему стандартный DRI3 не работает в Android / X11

Протокол **DRI3** (*Direct Rendering Infrastructure 3*) в настольном Linux X11 рассчитан на то, что:
1. Приложение и X-сервер делят общие GPU-буферы через `DMA-BUF` файловые дескрипторы на одном и том же устройстве DRM (`/dev/dri/card0`).
2. X-сервер является полноправным владельцем экрана (**DRM Master**).

### В Android это наталкивается на две аппаратные преграды:
1. **Монополия DRM Master**:
   * По правилам подсистемы DRM ядра Linux, только **один процесс** может обладать привилегиями `DRM_IOCTL_SET_MASTER`.
   * В Android этим мастером является служба аппаратного композитора **Qualcomm Composer HAL** (`vendor.qti.hardware.display.composer-service`, `android.hardware.graphics.composer`).
   * Ни Termux:X11, ни chroot-сервер не могут открыть `/dev/dri/card0` для вывода графики, пока работает Android.
2. **Несовместимость аллокаций памяти (KGSL vs MSM DRM)**:
   * Turnip на Adreno выделяет память в адресном пространстве KGSL.
   * Контроллер `/dev/dri/card0` ждет буферы формата Snapdragon Display Engine, синхронизируемые через проприетарный `Android Gralloc` и память `ION / dma-heap`.
   * При попытке использовать DRI3 в X11 приложение пытается вызвать DRM IOCTL-команды на `/dev/dri/card0`, натыкается на отказ в доступе (Permission Denied) и аварийно завершается.

## 4. Как решена эта проблема в NativOS

Чтобы избежать сбоев и получить максимум производительности от Adreno 619:

1. **Хук `libnodri3.so`**:
   * Перехватывает вызов `xcb_get_extension_data(..., "DRI3")` через `LD_PRELOAD`.
   * Возвращает `NULL`, сообщая графическим библиотекам, что DRI3 недоступен на данном X-сервере.
2. **Переменная `export MESA_VK_WSI_DEBUG=sw`**:
   * Указывает подсистеме Vulkan WSI (*Window System Integration*) использовать программный обмен кадров с X11 через разделяемую память (`MIT-SHM` / `libandroid-shmem.so`).
   * 3D-графика считается на полной скорости железом Adreno через `/dev/kgsl-3d0`, а готовый кадр копируется в X-сервер через разделяемую память без обращения к DRI3.
3. **Аппаратный композитинг `WLR_RENDERER=gles2` с авто-откатом**:
   * Вместо процессорной отрисовки `pixman` рабочий стол Phosh/phoc сводится через OpenGL ES 2 шейдерами GPU.
   * Супервизор содержит сторожевой таймер: при малейшем сбое GLES2 система мгновенно откатывается на безопасный CPU `pixman`, исключая бутлуп.
4. **Виртуальное масштабирование (Downsampling 80% / 67%)**:
   * На родном разрешении панели M17 (1080×2400) один 32-битный кадр весит ~10.4 МБ. При 60–120 FPS это перегружает шину памяти процессора.
   * Режим 80% снижает объем передаваемых пикселей на ~36%, а режим 67% (~720p) — в 2.5 раза. Android `SurfaceView` растягивает кадр на полный экран M17 аппаратным интерполятором без потери скорости.

## 5. Концепция Native Direct DRM/KMS Режима (в обход Android)

Поскольку у нас есть права `root` (KernelSU), теоретически возможно запустить Linux на панели M17 **напрямую на железе**, полностью отключив графический стек Android:

### Принцип работы:
```bash
# 1. Остановить графическую подсистему Android и освободить DRM Master
stop surfaceflinger

# 2. Теперь /dev/dri/card0 свободен!
# Композитор (phoc или sway) запускается с бэкендом прямого доступа:
export WLR_BACKENDS=drm
export WLR_DRM_DEVICES=/dev/dri/card0
phoc -C /etc/nativOS/phoc.ini
```

### Преимущества прямого режима:
* **Честные 120 FPS без единой задержки**: кадры отдаются видеоконтроллером прямо в развертку панели M17.
* **Нулевое копирование памяти (Zero-Copy)**: устраняются 3 промежуточных буфера SurfaceView и SurfaceFlinger.
* **Экономия RAM и батареи**: ядро Android не тратит ресурсы на работу домашнего экрана, шторки и сервисов Android.

### Возврат в Android:
```bash
start surfaceflinger
```
Android мгновенно перезапускает свой Composer HAL и восстанавливает стандартный интерфейс смартфона.

## 6. Полезные команды для быстрой диагностики в терминале

```bash
# Проверить статус подключения панели M17 и поддерживаемые герцовки:
cat /sys/class/drm/card0-DSI-1/status
cat /sys/class/drm/card0-DSI-1/modes

# Проверить текущую частоту обновления экрана:
dmesg | grep -i "refresh_rate" | tail -n 5

# Посмотреть, кто сейчас владеет контроллером экрана (/dev/dri/card0):
lsof /dev/dri/card0

# Проверить узел Adreno GPU:
ls -la /dev/kgsl-3d0

# Проверить текущую яркость панели M17:
cat /sys/class/backlight/panel0-backlight/brightness
cat /sys/class/backlight/panel0-backlight/max_brightness
```
